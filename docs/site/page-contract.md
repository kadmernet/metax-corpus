# The Page Contract

**What this instrument is.** The structural obligation every generated page in the
`metax.academy` estate must satisfy: its skeleton, its required components, its provenance
disclosures, and the acceptance checklist by which a page either ships or does not. It governs
the **container**. [ST-24](../standards/st-24-page-prose-standard.md) governs the **prose** inside
it, and the [Route Manifest](route-manifest.md) governs the **address** it lives at.

**Why a contract rather than a template.** A template is something an author starts from; a
contract is something a page can *fail*. That distinction is the whole design of this document.
Every clause below is written so that a build step or a reviewer can return a boolean, because a
requirement no one can fail is a preference wearing the costume of a rule. §9 is the checklist in
its executable form.

---

## 0. The contract's own thesis

Three hundred and twenty-one pages generated by agents against a specification will be
structurally uniform whether or not anyone intends it. That uniformity is a risk to be managed,
not a virtue to be celebrated, and this contract takes a specific position on which parts of a
page should be identical and which must vary.

**What must be identical:** the skeleton, the script order, the provenance stamp, the
related-page lattice, the exit pair, the accessibility floors, the demo strip. These are the
*infrastructure of trust*. A reader who learns on one page that the pagestamp tells them the
evidence class and the review date must find it in the same place on all 321, or the disclosure
becomes a decoration that happens to be present.

**What must vary:** which section leads, the register the page opens in, the shape of the worked
instance, the vocabulary of the falsifier. These are the *substance*. A body of pages identical
in substance is a database with a stylesheet, and the estate would have produced — in the words
of the specification it derives from — *"a manual rather than an academy."*

The contract therefore fixes the container tightly and deliberately says almost nothing about the
argument, and every clause below should be read as an answer to one question: **does this belong
to the infrastructure of trust, or to the substance?** If the former, it is mandatory and
checkable. If the latter, this document is silent and ST-24 speaks.

## 1. The skeleton

```html
<!DOCTYPE html><html lang="en">
<head>
  <meta charset="UTF-8"><meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="theme-color" content="#05060f">
  <title>{Page Title} — {Pillar} · MetaX.Academy</title>
  <meta name="description" content="{150–160 chars, declarative, no marketing verbs}">
  <link rel="canonical" href="https://metax.academy{/route/}">
  <link rel="alternate" hreflang="en" href="https://metax.academy{/route/}">
  <link rel="alternate" hreflang="ar" href="https://metax.academy/ar{/route/}">
  <link rel="stylesheet" href="/css/style.css">
  <script type="application/ld+json">{ "@type": "{Article|Course|WebPage}", … }</script>
</head>
<body class="page-fade">
  <div class="cosmos" aria-hidden="true"></div>
  <div class="grid-veil" aria-hidden="true"></div>
  <div id="site-header"></div>
  <main>
    <section class="hero wrap">
      <span class="eyebrow">✦ {PILLAR} · {GROUP}</span>
      <h1>{claim, not a label}</h1>
      <p class="lead">{one sentence, ≤32 words, states what the reader will be able to do or check}</p>
      <div class="mx-pagestamp">{status badge} · {evidence class} · {version} · reviewed {date}</div>
    </section>
    <div class="marquee" aria-hidden="true">…</div>
    <!-- 6–9 .reveal sections, per ST-24 -->
    <section class="wrap reveal"><nav class="mx-related">…</nav></section>
    <section class="wrap reveal"><div class="cta-band mx-exitpair">…</div></section>
  </main>
  <div id="site-footer"></div>
  <script>window.SITE_PAGE = { ver:"{PILLAR} · v2026.10", cta:{label:"…", href:"…"} };</script>
  <script src="/js/data.js"></script><script src="/js/components.js"></script>
  <script src="/js/skeleton.js"></script><script src="/js/site.js"></script>
  <script src="/js/page.js"></script>
</body></html>
```

### 1.1 Three clauses in the skeleton that are not cosmetic

**`<h1>` is a claim, not a label.** "The Decay Standard" is a label. "A technical claim has a
half-life, and publishing it without one is a defect" is a claim. The rule exists because a
corpus of 321 labels is an index, and an index cannot be disagreed with. A claim can, which is
what makes it academic writing rather than documentation.

**`.lead` is capped at 32 words and must state what the reader will be able to *do or check*.**
The cap is arbitrary in the way all caps are; the requirement to name a capability or a check is
not. It forces every page to answer the question a reader silently asks — *why am I on this
page?* — in the first sentence rather than in the fourth section.

**`meta description` forbids marketing verbs and must be declarative.** 150–160 characters, no
*unlock, supercharge, revolutionise, empower, seamless, cutting-edge, game-changing*. This is the
only text most readers will ever see, and an estate publishing a harms register that names
attention expropriation cannot write its own search snippets in the grammar of the attention
economy.

### 1.2 Script order is load-bearing

`data.js` → `components.js` → `skeleton.js` → `site.js` → `page.js`, and
`window.SITE_PAGE` must be set **before** `components.js`.

The order is not a convention; it is a dependency chain, and it fails in a way that looks like a
content bug rather than a build bug. `components.js` reads `SITE_PAGE` at parse time. If the
inline configuration block moves below it — an easy and invisible edit — the header renders with
an empty version stamp and no CTA, and nothing in the console indicates why. Recorded because it
is the kind of failure that gets diagnosed as "the header is broken" for an afternoon.

### 1.3 Ambient layers are `aria-hidden`

`.cosmos`, `.grid-veil` and `.marquee` are decorative and must carry `aria-hidden="true"`. The
marquee in particular is a moving text strip: exposed to a screen reader it interleaves
meaningless fragments into the page's reading order, which is worse than absent. Decoration that
is not marked as decoration becomes content for exactly the readers least able to ignore it.

## 2. `.mx-pagestamp` — the disclosure strip

Directly beneath the `.lead`, four facts in one line:

```html
<div class="mx-pagestamp">
  <span class="mm-badge badge-live">live</span> ·
  <span class="ps-evidence">semi-durable</span> ·
  <span class="ps-version">v2026.10.1</span> ·
  <span class="ps-reviewed">reviewed 2026-10-01</span>
</div>
```

| Field | Values | Why it is on every page |
|---|---|---|
| Status badge | `live` · `planned` · `research-preview` · `gated` | A reader must not have to infer whether a page describes something that exists |
| Evidence class | `durable` · `semi-durable` · `perishable` | Tells the reader how fast this page goes stale before they rely on it |
| Version | The instrument or estate version | Makes the page citable to a state, not just to an address |
| Reviewed | ISO date | A review date absent is a claim that nobody has checked |

**This is the single most load-bearing component in the contract.** Every other element helps a
reader navigate; the pagestamp is what lets them *discount*. A page that says "semi-durable,
reviewed 2026‑10‑01" is telling a reader in 2029 to treat it with suspicion — and an estate
willing to say that on all 321 pages has made a structural commitment that no amount of prose
about epistemic humility can substitute for.

Under [ST-05](../standards/st-05-decay-and-review-intervals.md) the evidence class also
determines the review interval, so the field is not merely informational: it is the input to the
schedule that keeps the page true.

**Provenance of purpose.** Where a page makes a claim about a live artefact, the pagestamp
additionally carries `demo`, `staging` or `production`. This field is new, arising from
[C-14](../00-governance-map/corrections-log.md#c-14) and
[DEF-024](../00-governance-map/defect-register.md#def-024): nine claims published in v2026.09.4
were true of the bytes read and silent about what those bytes were *for*.

## 3. `.mx-related` — the lattice

Every leaf page ends with exactly four link groups, rendered as `.rails` 2-up on desktop.

| Group | Contains | Count |
|---|---|---:|
| **Up** | Its group hub and its pillar hub | 2 |
| **Beside** | Sibling leaves in the same group | 3–5 |
| **Depends on** | Prerequisites or upstream standards, **cross-pillar** | 1+ |
| **Governs / governed by** | The ML‑2.3 duty or Method standard constraining this page | 1+ |

**A leaf with fewer than eight outbound internal links is a build failure.** The source's
justification is exact: *"this is what makes 321 pages a lattice rather than a pile."*

### 3.1 Why the fourth group is a governance mechanism

The first three groups are ordinary information architecture. The fourth is not, and it deserves
the emphasis this section gives it.

Requiring every page to name **the duty that constrains it** means [ML-2.3](../license/ml-2-3.md)
is reachable in one hop from anywhere in the estate. That is a categorically stronger guarantee
than a footer link, and it is the mechanism by which the License becomes *operative* rather than
merely *published*. A licence one hop from every claim is a licence a reader can hold the estate
to; a licence in the footer is a licence nobody opens.

It also imposes a discipline on the author that is the real reason for the rule: **you cannot fill
in this group without knowing which duty your page is subject to.** A page whose "Governs" field
is hard to fill is usually a page whose author has not decided what kind of claim it makes. The
group is therefore a diagnostic as much as a navigation aid, and pages that resist it should be
re-scoped rather than given a plausible-looking citation.

### 3.2 The cross-pillar requirement

`Depends on` must reach **outside the current pillar**. Without that constraint a pillar becomes
a silo that cites only itself, and the estate's claim to be one body of knowledge rather than nine
adjacent ones becomes untestable. The check is mechanical: at least one `Depends on` target whose
first path segment differs from the page's own.

## 4. `.mx-exitpair` — exactly two actions

Every page closes with **two** actions: one that goes **deeper** (a leaf or parametric page) and
one that goes **sideways** (another pillar).

**No third action. No newsletter capture. No urgency copy.**

The prohibition is the substance of the clause. Every additional call to action converts a page
from a document into a funnel, and the estate publishes a register whose Stratum I names
attention expropriation as a structural harm. Two actions is the smallest number that still
respects both of a reader's legitimate intentions — to go further into a subject, or to leave it
for another — and the largest number that cannot be used to manufacture a decision. A page with
five exits is not more helpful; it is a page that has decided the reader's next move matters more
than their current one.

## 5. `.mx-demo` — the provenance strip

Until the estate declares itself out of demo, every page renders directly beneath the header:

```html
<div class="mx-demo" role="note">
  <strong>Demo build.</strong> This estate is under construction. Counts, catalogues and
  statuses render from dated data files; prose marked <em>scaffold</em> has not been reviewed.
  <a href="/about/universe/demo-notice/">What is real and what is not →</a>
</div>
```

**Styling:** `--panel` ground, 1px `--line` border, `--gold` left rule 3px, 0.85rem, **no
animation**. Dismissible for the session only, via `sessionStorage`.

**Never hidden on `/license/`, `/about/status/` or `/metax/bcia/`.** These three are the routes a
reader visits precisely to check whether the estate is honest, and they are the three where a
dismissed banner would do the most damage.

### 5.1 What the strip does and does not discharge

The strip discharges the duty to **disclose** scaffolding. It does not discharge the duty to
**write**. A page of placeholder prose behind an honest banner is still a page that should not
have shipped, and [B-20](../00-governance-map/launch-blockers.md) closes on disclosure while the
word floor and this checklist close separately.

The reasoning, stated so it cannot be misread later: an estate that knows it is a demo and does
not say so commits **HX‑15** on the exact pages a reader would consult to check whether it commits
HX‑15 ([DEF-025](../00-governance-map/defect-register.md#def-025)). But an estate that says so and
then treats the banner as a licence to publish anything has merely relocated the harm. Disclosure
is a floor, not a defence.

**No animation on this element, specifically.** A banner that fades, slides or pulses is asking
for attention in the idiom the estate's own register criticises. It should read as a legal notice,
because it is one.

## 6. CSS the contract requires

Nine additions, listed with their status.

| Rule | Purpose | Status |
|---|---|---|
| `prefers-reduced-motion` block | Suppress all nine ambient animations | **Unshipped, launch-blocking** — [B-16](../00-governance-map/launch-blockers.md) |
| 1180px nav breakpoint | Nine pillars do not fit at 1000px | Required |
| `.mm-hub` | Group heading renders as a link | Required |
| `.mx-pagestamp` | §2 | New |
| `.mx-related` | §3 | New |
| `.mx-exitpair` | §4 | New |
| `.mx-demo` | §5 | New |
| `.ul-word` | Utility-link word wrapper for the glyph-only state | New |
| `.nav-toggle{min-height:44px}` · `.btn{padding:15px 26px}` | Touch-target floor | **Fixes [DEF-022](../00-governance-map/defect-register.md#def-022)** |

### 6.1 The reduced-motion block is not optional

The live token layer runs **nine infinite animations** with no `prefers-reduced-motion` escape
([R-44](../00-governance-map/reconciliation-ledger.md),
[DEF-016](../00-governance-map/defect-register.md#def-016)). This is the estate's oldest
accessibility defect and the one it is least able to justify, because the user preference exists
precisely so that a site need not guess: the reader has already answered.

It is a **design-system** defect, not a demo defect. That distinction matters after
[C-14](../00-governance-map/corrections-log.md#c-14) re-levelled the live-code findings: the token
layer is what the demo was built to establish, so this defect is inherited by production intact.
It survives the demo correction at full authority and remains launch-blocking.

### 6.2 Touch targets

`.nav-toggle` at 42px and `.btn` at `14px 26px` both fall below the 44px floor —  by a small
margin, on a conformance claim in [MX-010](../corpus/mx-010-accessibility.md) that **a ruler
falsifies**. That last property is what makes it worth fixing before launch rather than after: it
is the cheapest possible falsification of an accessibility claim, requiring no expertise and no
assistive technology, only measurement.

## 7. Group headings render as links

```js
var head = f.hub
  ? '<h6><a class="mm-hub" href="' + f.hub + '">' + f.heading + '</a>' + badgeHtml(f.badge) + '</h6>'
  : '<h6>' + f.heading + badgeHtml(f.badge) + '</h6>';
```

`.mm-hub` inherits `<h6>` type and gains `color: var(--cyan)` on hover with a 1px underline at 3px
offset. Utility links wrap their word in `<span class="ul-word">` and expose their glyph in a
sibling `<span aria-hidden="true">` with an `aria-label` on the anchor, so the glyph-only state
between 1180px and 1280px stays accessible.

The `f.hub` ternary is what makes the estate's third tier reachable. Before it, a group heading
was a label inside a panel and its 45 hub pages were unreachable from the navigation — present in
the manifest, absent from the interface. A route that exists and cannot be reached is worse than
one that does not exist, because it will be found by a crawler and not by a reader.

## 8. Structured data

One `application/ld+json` block per page, `@type` one of `Article`, `Course` or `WebPage`.

`Course` is reserved for `/toptech/s/{S##}-{slug}/c{NN}/` routes only. It carries eligibility
implications in search results, and applying it to a hub or a standards page would be a
machine-readable overstatement of what the page is — the structured-data equivalent of a marketing
verb, and equally forbidden.

## 9. The acceptance checklist

A page ships only when **every** line holds.

| # | Criterion |
|---:|---|
| 1 | Word count ≥1200, or `mx-thin` declared and filed under DEF‑2026‑043 |
| 2 | All eight ST-24 recipe sections present, each with an `<h2>` |
| 3 | `.mx-related` carries the four groups and ≥8 internal links, all resolving |
| 4 | At least one `Depends on` target is cross-pillar |
| 5 | `.mx-pagestamp` shows status, evidence class, version, review date |
| 6 | `.mx-exitpair` has exactly two actions |
| 7 | Demo strip present unless the estate has left demo |
| 8 | All paths root-absolute |
| 9 | Canonical and both `hreflang` tags correct, trailing slash present |
| 10 | `window.SITE_PAGE` set before `components.js`; script order correct |
| 11 | Nine `.mm-top` items render; the correct one carries `.active` |
| 12 | Every `.mm-badge` has a text label and one of the four permitted values |
| 13 | No number without a date or `data-count-src` |
| 14 | `.img-slot` renders its shimmer with no image file present |
| 15 | Page legible with CSS disabled |
| 16 | Page renders its main prose with JavaScript disabled |
| 17 | Contrast ≥4.5:1 against every gradient used |
| 18 | Touch targets ≥44px |
| 19 | The reduced-motion block suppresses all nine ambient animations |
| 20 | **MacroLifeTech** spelt correctly in every instance |

### 9.1 Three lines that are currently failed by the estate itself

**Line 16** — no-JavaScript rendering. The live demo renders nothing without JS: no header, no
footer, no navigation, no pillars ([DEF-018](../00-governance-map/defect-register.md#def-018),
[RAT-17](../00-governance-map/open-questions-and-ratifications.md#rat-17)). Every page generated
under this contract must satisfy line 16, which means the contract is stricter than the artefact
it derives from. That is the correct direction for a contract to point.

**Line 19** — reduced motion. Unshipped, per §6.1.

**Line 14** — `.img-slot`. Worth a clarification that is easy to get wrong: the shimmer
placeholder is the **default rendered state**, not a loading state. The estate operates a
**no-image regime** ([`/about/policy/no-images/`](route-manifest.md#59-about--35-routes)), so a
slot with no image behind it is correct and permanent, not a missing asset. A build check that
flags empty `.img-slot` elements as errors has misunderstood the design.

### 9.2 Line 13, and why it is the hardest to keep

*"No number without a date or `data-count-src`."*

This is the line most likely to be violated by a careful author acting in good faith, because
numbers are how prose earns credibility and the discipline of sourcing every one is tedious. It
is also the line whose violation is most damaging: a typed count is a claim with no falsifier, and
[the defect register](../00-governance-map/defect-register.md) records that a typed count which
*undercounts defects* is the specific failure it exists to prevent.

The mechanism is `data-count-src` pointing at a JSON path, so the number is rendered from the same
artefact that would be audited. Where no such artefact exists, the number needs a date, which at
least tells the reader when it was true.

## 10. Limits

**This contract governs containers, not arguments.** It cannot detect a well-structured page that
is wrong, and it cannot detect a page that satisfies all twenty lines while saying nothing. Both
are ST-24's domain and neither is mechanically checkable — which is the honest limit of a
checklist and the reason [RAT-21](../00-governance-map/open-questions-and-ratifications.md#rat-21)
treats authorship, not structure, as the open question at volume.

**It cannot enforce variation.** §0 requires that pages differ in substance, and no clause here
can test for that. A build passing all 321 pages tells the estate its infrastructure is sound and
tells it nothing about whether it has published one argument 321 times.

**It does not decide the ad question.** Lines 1–20 are silent on whether ad slots may appear on a
content-plane page, because that is
[RAT-15](../00-governance-map/open-questions-and-ratifications.md#rat-15) and it is the Curator's.
The contract records only that if they stay, `/license/statement/ours/` must say so.

---

## 11. Falsifier

This contract is wrong if a page satisfying all twenty acceptance lines is nonetheless
unpublishable — which would show the checklist to be incomplete rather than strict — or if a page
failing one line is nonetheless clearly publishable, which would show that line to be a
preference misfiled as a rule.

The second is the likelier failure and the estate should watch for it in one specific place: line
1, the word floor. [DEF‑2026‑043](../00-governance-map/defect-register.md#def-2026-043) already
records six page classes where the floor would produce padding. If a seventh, eighth and ninth
appear, the floor is wrong and should be re-derived rather than exempted case by case — an
exemption list that grows page by page is a rule dissolving while pretending to hold.

---

## 12. Obligation

For the **build agent**: emit no page that fails §9. Where a line cannot be satisfied, emit
nothing and report the page as blocked. A reported gap is a smaller harm than a page that looks
complete — this is §7.4's principle applied to structure rather than to prose.

For the **reviewer**: check lines 3, 4, 6 and 13 by hand. The others can be automated; these four
require judgement, because a resolving link can still be the wrong link and a sourced number can
still be the wrong number.

For the **editor**: any change to §§1–8 is a specification change requiring a changelog line at
[`changelog.md`](../00-governance-map/changelog.md), because the twenty acceptance lines are what
321 pages were built against, and changing one silently invalidates every page that passed.
